# AM-PKO EXP-4B6-001 Query Design Specification

**Experiment:** EXP-4B6-001  
**Status:** DESIGN  
**Query design version:** 0.1-design  
**Corpus dependency:** Frozen EXP-4B6 corpus v0.1

## 1. Purpose

Define a model-neutral query set for evaluating whether the frozen 50-record corpus supports useful retrieval across direct, ambiguous, overlapping, contradictory, relationship-dependent, and cross-domain knowledge needs.

Queries must test retrieval behavior rather than reproduce corpus titles or mechanically restate record content.

## 2. Query Count

Target query count: **50**

Target mapping: one primary query per corpus record, while allowing each query to test retrieval against the wider corpus.

The query set must not assume that the intended record is always the highest-ranked result.

## 3. Query Classes

The query set must contain all of the following classes:

1. Direct retrieval
2. Ambiguous retrieval
3. Semantic-overlap discrimination
4. Contradiction-aware retrieval
5. Relationship-dependent retrieval
6. Cross-domain retrieval

Each class must contain multiple queries.

## 4. Query Independence

Queries must be authored after corpus freeze.

Query authorship must not alter the frozen corpus.

Queries must not be generated by copying record titles.

Queries must not contain candidate model names or model-specific terminology.

Queries must not encode an expected ranking or metric outcome.

Judgments must be created separately from query authoring.

## 5. Query Structure

Each query record will contain at minimum:

- query_id
- query
- query_class
- target_record_ids
- rationale

`target_record_ids` identify records considered relevant for evaluation purposes and are not a retrieval instruction.

## 6. Ambiguity

Ambiguous queries must represent genuine uncertainty between multiple plausible records.

They must not be artificially vague.

The ambiguity must arise from shared concepts, context, terminology, or possible interpretations represented in the frozen corpus.

## 7. Semantic Overlap

Semantic-overlap queries must test whether retrieval can distinguish closely related records whose meanings are not identical.

Relevant records may share terminology while differing in knowledge type, context, provenance, or intended application.

## 8. Contradiction

Contradiction-aware queries must test whether competing propositions can remain discoverable rather than being silently collapsed into one answer.

Where appropriate, the expected relevant set should include both sides of a documented contradiction.

## 9. Relationship Dependence

Relationship-dependent queries must require inspection of related records to fully understand the intended knowledge context.

The query itself must not encode the entire relationship chain.

## 10. Cross-Domain

Cross-domain queries must connect concepts or relationships across different domains without assuming that similarly named concepts have identical meanings.

## 11. Human Utility

Queries should resemble plausible knowledge-use situations.

They should test whether retrieved records provide enough identity, context, provenance, relationship, and distinction information for a person to judge usefulness.

## 12. Evaluation Independence

Judgments will be authored independently after query construction.

No query may be changed merely to improve a model's observed retrieval result.

Any query revision after judgment freeze requires an explicit lifecycle transition and validation record.

## 13. Frozen-Core Protection

Query design must not modify:

- I-2
- I-3
- I-4
- I-5
- I-6
- T-5
- T-6
- T-7
- Contract Graph

No production embedding model or vector database is selected by this design.

## 14. Lifecycle

The intended lifecycle is:

`DESIGN → GENERATED → VALIDATED → FROZEN`

Only a frozen query set may be used for comparative embedding evaluation.

## 15. Exit Criteria

Query construction may proceed only after:

- all six query classes are represented;
- query IDs are unique and stable;
- every query references valid frozen corpus IDs;
- no query contains model-selection language;
- no query modifies the corpus;
- target relevance is independently judged;
- the query set passes its dedicated validation gate.

**Current state: DESIGN ONLY.**
