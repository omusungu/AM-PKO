# AM-PKO ER-10 — Canonical Embedding Document Specification

Status: RECOVERED_FROM_ARCHITECTURE
Implementation dependency: I-2 EmbeddingDocumentGenerator

## Purpose

ER-10 defines the deterministic transformation from a canonical
KnowledgeRecord into the canonical EmbeddingDocument text consumed
by I-3 EmbeddingModel implementations.

## Canonical EmbeddingDocument

Required fields:

- record_id
- record_version
- embedding_spec_version
- document_text
- document_hash

## Canonical document template

The document begins with:

[<KNOWLEDGE_TYPE> / <GRANULARITY>]

The fixed semantic fields are represented using deterministic labels:

Domain:
Project:
Topic:
Title:
Content:
Skills:

## Determinism

For the same KnowledgeRecord and the same embedding_spec_version:

- document_text MUST be byte-identical.
- document_hash MUST be byte-identical.
- whitespace normalization MUST be deterministic.
- trailing whitespace MUST NOT be present.
- field labels MUST remain fixed.
- empty approved fields retain their labels.
- no nondeterministic component may participate.

## Approved transformation

ER-10 is a deterministic formatting transformation only.

No LLM or semantic rewriting is permitted.

## Excluded from embedding document text

The following are not included in document_text:

- record_id
- status
- source
- metadata
- assets
- actions
- relationships

These remain available through the canonical record/vector payload
rather than being embedded into semantic document text.

## Versioning

embedding_spec_version identifies the exact ER-10 formatting specification
used to generate document_text and document_hash.

A change to the embedding specification changes the embedding specification
version and requires affected vectors to be regenerated.

## I-2 boundary

I-2 is responsible for:

KnowledgeRecord -> deterministic EmbeddingDocument

I-2 is not responsible for:

- embedding model execution
- vector generation
- vector storage
- retrieval
- ranking
- graph traversal
- semantic rewriting
